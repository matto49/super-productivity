# Settings And Preferences

The Settings screen is the source of truth for available options and defaults.
This page documents selected behavior that is not obvious from the labels; it
is not an exhaustive copy of every setting. Platform differences are described
in [[3.05-Web-App-vs-Desktop]].

## Global Settings

A search box sits above the settings tabs. Typing into it searches every tab at
once and lists the matches in a dropdown, each showing the section it belongs to
and, where a specific option matched, that option's label. Picking a result
switches to the tab it lives on, expands the section, and scrolls to it.
Searching for a tab name lists everything on that tab. Settings that are not
collapsible sections — dark mode, theme, wallpaper, sound, plugins, and sync
setup — are searchable too.

### Localization

- **Datetime format locale** — Controls numeric date formatting and the
  12/24-hour time format. The ISO 8601 option uses `YYYY-MM-DD` and a 24-hour
  clock. With ISO 8601 selected, weekday labels in Schedule, Habits, and Planner
  follow the app language. The System default option follows your browser or
  operating system regional locale; when formatting data for a locale is not
  available, dates fall back to British English (en-GB) formatting.

### Miscellaneous

- **Show current countdown in the tray / status menu (macOS only)** — Shows the
  active timer or countdown in the desktop status menu title. When this is
  disabled and current-task display is enabled, the title can show the current
  task instead.
- **Automatically check for new versions (desktop only, default: on)** — Once a
  day the desktop app asks the GitHub releases API whether a newer version has
  been published and shows a dismissible notice linking to the download page.
  No personal data is sent, nothing is installed automatically, and each
  version is announced at most once. The setting (and a manual "Check for
  updates" link in the settings footer) only appears on builds without their
  own update channel; Microsoft Store, Mac App Store, and Snap builds update
  through their stores and never check.
- **Enable local REST API (desktop only, default: off)** — Starts a localhost
  HTTP API on `http://127.0.0.1:3876` for local scripts and tools. Every request
  except `GET /health` must include the generated access token as
  `Authorization: Bearer <token>`. The token is shown below this setting and can
  be regenerated, which invalidates the previous token immediately. This is a
  breaking change for older API clients that used the API without authentication.

### Tasks

- **Show current task in the tray / status menu (macOS/Windows only)** — Allows
  the desktop tray or status menu to show the active task. On macOS, the current
  countdown setting takes priority while it is enabled.

### Short Syntax

- **Enable deadline short syntax** — Parses `!<deadline time>` while entering task
  titles. This option is disabled by default.

### Idle Handling (removed in this fork)

Automatic idle detection and the time-allocation dialog have been removed. Task
timers continue until stopped manually. Legacy idle settings in backups are
accepted for compatibility but have no effect.

## Sync & Export

### Automatic Backups

- **Enable automatic backups** — Creates local backups automatically when supported by the current platform.
- **Restore latest automatic backup** — Android only. Restores the latest usable automatic backup and replaces the current local data after confirmation.
- **Maximum backup files** — Desktop only. Limits how many automatic backup JSON files are kept in the `backups/` folder; older files are deleted once the limit is exceeded.

## Project, Tag, Today, And Inbox Settings

### Basic Settings

- **Enable Project Backlog** — Adds a separate backlog list to the project.
- **Hide project from sidebar** — Removes the project from the sidebar project list. The project stays active: its tasks can still appear in cross-project task views such as Today, Planner, Schedule, Boards, and Search. The sidebar visibility menu remains the place to show the project again; project short syntax does not match hidden projects.

### Theme

Theme settings can include background images for light mode, dark mode, or both.
When at least one background image is set, the background contrast and blur
sliders are shown. The blur slider defaults to `0px`. When at least one mode has
no background image, the colored background tint setting is shown. See
[[3.09-Theming]] for theme details.

## Desktop task widget: task lists (local fork)

Under **General → Task Widget**, **Widget content** selects the current-task timer,
Today's tasks, or all open top-level tasks. List modes show tasks without starting
any timer. Today uses the same planned-day membership and order as the main app.
All open tasks includes all active projects, including Inbox; completed and archived
tasks are omitted. A selected project also shows its open subtasks beneath their
parents. Completing a parent applies the app's normal subtask behavior.

Enable **Always show task widget** to keep it visible while the main app is open.
The widget stays on top across desktops. Drag its header to move it and resize its
edges; list mode remembers its size separately from timer mode. Check a task to
complete it through the app's normal task/sync flow, or use the arrow to open the
main app. The app must remain running; no local REST API or extra server is needed.

Widget preferences are device-local. This mode does not add parallel timers.

### Parallel work in the desktop task list (local fork)

The list uses a light card appearance independent of the system theme. Status
and session-jump icons share the title row; hover to see their labels or a full
truncated title.

Each top-level task has an **In progress** toggle. This uses an ordinary tag, syncs
with the task, and does not start the single personal timer. Multiple tasks can be
in progress at once. In-progress tasks appear first in both list modes; tasks
with the same status keep their original relative order. Completing a task removes
it from the open-task widget.

The optional local activity bridge shows **AI elapsed** and **Review (estimated)**
when observations have been imported. Review estimates on leaf tasks enter native
task/day work logs and project reports; parent receipts leave derived native totals
alone. Parallel AI durations are separate and must not be
interpreted as personal work time. The widget totals cover imported days.

For a task with a Markdown link to an existing Codex session in its notes
(`codex://threads/<session-uuid>`), the desktop list also shows **Open Codex**.
Click it to open that session in the installed Codex application. This works with
local and connected remote-host sessions; it neither submits a message nor starts
a timer. If several session links exist, the first valid link is used. Tasks
without a link have no jump button. Session links sync as ordinary task notes.
Only existing-session links without extra paths or query parameters are accepted.

In the task list widget, click a task title to edit it. Enter or leaving the field saves; Escape cancels. The + button adds a task to Inbox (also planned for today when using the Today view). Empty titles are ignored. Changes use the usual task storage and sync.

### Linked task list widget

The widget edits the same task records as the main application. It supports
focus (in progress or awaiting review), all open tasks, Today and project views.
Status uses the native Kanban in-progress tag and a separate awaiting-review tag;
importance and urgency use the native Eisenhower tags. These dimensions are independent.
Today plans a task for today; project selection moves it through the standard task service.
The detail shortcut opens the same task in its main project view.

Drag ordering is stored in the underlying project or Today order, preserving hidden tasks.
Across-project drag is not supported in aggregate views. The foreground-human estimate
comes from imported receipts. The native tracked total, including manual adjustments,
remains separate; AI time never counts as personal work time.
The authorized one-time setup consolidates active work in Work, retains Waiting as a tag,
replaces the legacy progress tag, and adds a review column without changing the Eisenhower board.

The widget has Focus (in progress or awaiting review), Today, All, and project
scopes. Opening Today or a project in the main app updates the widget's scope;
choosing Today or a project in the widget opens the same main-app context. Focus
and All remain aggregate widget views. The main task row and widget both show
separate cumulative AI and foreground-human estimates from activity receipts;
the native tracked-time value remains the app's personal work log. An absent
receipt is not evidence that a collector ran and found zero activity.

Within each widget view, in-progress tasks appear first, followed by tasks awaiting
review and then other tasks. Within each status group, tasks marked important or
urgent appear before unmarked tasks; either flag has the same sorting priority.
Changing these flags updates the order automatically. Dragging preserves manual
order within the same priority and project (or across projects in Today).

The widget status button shows a gray hollow dot for To do and a green filled dot
for In progress. Click it, or focus it and press Enter or Space, to switch between
the two states. Hover to see the current and next state. The dot has the same click
area as the other row actions. Tasks carrying the existing awaiting-review tag
show the To do indicator; displaying them does not change their tags or recorded time.

### Codex association coverage in the task widget

When the optional local activity bridge projects a canonical association, the
widget opens its default Codex thread. It displays collection checked, scope
needs review, reference not collected, session unavailable, or stale collection.
Hover over the status for the collection start, last check, associated thread
count, and whether review estimates were refreshed. A projection older than
15 minutes is marked stale on the next task-data refresh. Existing ordinary
Codex links continue to work and show collection unverified.

AI elapsed is cumulative agent runtime, including tools and waits; it is not
human work time. Missing collection does not display an invented zero AI metric.
Historical totals remain visible while association scope is under review.

### AI-assisted capture and daily planning

The widget offers one capture input and Plan my day. The previous row of planning
navigation shortcuts has been removed. Each task shows its current schedule;
project, priority, collection details and manual scheduling are inside Adjust.

A narrow, explicit Chinese capture format (Today/Tomorrow, optional exact time,
and numeric estimated duration) can be saved directly. Ambiguous wording,
deadlines, past times and conflicts fall back to suggestion review. Other input
uses the configured model and remains a preview: date, time and duration can be
edited before accepting. Just save the task keeps the original input in Inbox
without model scheduling. Inbox is the holding place for unclassified tasks.

Plan my day considers existing open tasks, priorities, schedules and estimates.
The editable budget defaults to 240 minutes and includes already planned work.
Suggestions cannot invent task IDs, overwrite existing schedules, exceed the
requested model-planning budget or overlap known timed tasks. External calendar
meetings are not included. Each suggestion is accepted separately. Model/network
failures leave tasks unchanged and allow ordinary capture.

The optional model configuration is a private `ai-planner.json` in Electron's
user-data directory, with `baseUrl`, `apiKey` and `model`. It is read only by the
main process; keys never enter the widget renderer. The integration uses a
Responses-compatible endpoint and sends task metadata and the entered request,
not notes, conversations or collected activity. The current local installation
uses the existing CPA connection. Planning itself does not run on a timer.

Planning suggestions now appear as a compact preview with estimated effort and
collapsed adjustments. Make this my plan adopts the visible suggestions in order;
only confirmed saves leave the preview. Successful tasks appear in Today, while
failed items remain available for review. Empty-list messaging and the saved task
count are suppressed while a preview is visible. The time budget opens on demand.
Undo reverses confirmed suggestions from the current preview. It restores the
previous estimate and removes the added schedule, or removes a newly created task,
only if that task has not changed since adoption. Later user edits are preserved.
Undo receipts are local to the running app and are not retained after restart.

Minute-based AI estimates and the daily time budget have been removed. Suggestions
contain task and date information only and select at most two daily priorities.
Accepting a suggestion no longer writes an estimated duration. Existing manual
estimates and observed activity are independent of this feature. Without durations,
planning does not claim to verify complete interval availability. The widget header
now offers two stable buttons, Today and All tasks, instead of a mixed dropdown of
statuses, projects and dates. Project controls remain inside task details.
