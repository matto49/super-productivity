## 用户预期

每条 Todo 能看出“在哪个会话推进、统计覆盖到哪里”，点击直接继续。
关联和计时覆盖分别展示：已关联 / 待关联 / 关联待确认；采集中 / 未接入 /
同步中断 / 范围待确认。没有记录时显示“未采集”，不直接显示零。

## 建议的数据与流程

建立一份权威关联记录，按稳定 taskId 关联，不通过标题推断身份：

```text
taskId
  links[]
    threadId + hostId
    role: primary | supporting | background
    scope: pending | wholeThread | selectedTurns | excluded
    turnIds[]（仅 selectedTurns）
    verifiedAt + verificationSource
  revision
```

标题只用于展示。hostId 对应独立的本机采集配置（连接方式、Codex 根目录），
不将本机绝对路径混入同步任务。当前采集器硬编码 ~/.codex，必须支持显式
profile 根目录，才能覆盖独立环境的门禁和安全工单会话。

一条 Todo 可以有多个执行或参考会话，只有一个默认打开入口。
同一会话可以被多个 Todo 引用，但同一轮次只能计入一个 Todo；冲突显式
报出，不静默重复累计。background 默认不计时；不因链接存在就启用 wholeThread。
继续、归档、改名不改变身份；换会话保留旧关联，追加新执行会话。

迁移时从 notes 导入候选，结合三套旧绑定核查，不通过标题自动合并。
保留 notes 的普通链接以兼容旧客户端；打开入口、观察器和计时配置最终均从
权威关联生成。旧 title 字段可能是前台窗口匹配规则，不可批量替换成 Todo 标题。

建议先在 bridge 侧实现版本化映射文件和只读预览，验证范围后再接入任务界面；
持久化进同步任务前，另行评估同步兼容性。避免一次改动任务存储、采集器和界面。

## 时长与验收

保留可追溯记录：taskId、hostId、threadId、turnId、起止时间、来源、映射版本。
会话内区间取并集；任务下多会话并行时区分 AI 累计运行时间与自然经过时间，
二者不可混用。人工投入与 AI 运行分别展示，不能相加成总工作时长。
中断、未定位到会话、未绑定、区间外无记录分别标记。

实施顺序：

1. 当前已完成：六项关联定位、覆盖审计、只读工具与测试；私人核查文件留在仓库外。
2. 实施统一映射与校验：补齐机器/profile，确认 sol-ltm 和历史会话范围；
   通过显式绑定和范围选择解决歧义，禁止按相似标题自动认领。
3. 接通采集：从统一映射生成采集输入，支持多个配置目录；先预览新旧账本差异，
   再按来源替换，保留人工填写时间；重复执行不重复计时。
4. 界面：Todo 显示关联状态、默认会话入口、最近同步与统计范围；详情允许追加
   会话和选择计时范围，不要求用户维护多套配置。

验收场景包含：Todo 改名不丢关联；跨机器和配置环境正确定位；一个 Todo
多会话；共享会话不重复计时；历史参考不自动计时；断线不显示零；修正范围后
可追溯重算；旧客户端仍能打开 notes 链接。

## 只读审计工具

```bash
python3 tools/activity-bridge/audit_mappings.py --config /path/to/config.json --project-id PROJECT_ID
python3 -m unittest discover -s tools/activity-bridge -p test_audit_mappings.py
```

工具读取本地任务 API 和指定配置，只输出任务元数据、链接及覆盖差异。
不会修改任务、历史工时、绑定或自动化，也不会读取或输出会话正文。
其 semanticVerification 始终为 not_checked；会话内容核查必须单独记录，
不能将配置一致性检查伪装为语义验证。
